Tracked via Keep-Alive Probes; Paths Ranked by Quality", owning module
`internal/paths`) is exercised by this story's harness but was not anchored
in `behavioral_contracts:`/`bc_traces:`/Anchors Consumed prior to this edit.

`multipath.Send` calls `paths.Rank()` on every send (`multipath.go:252`), so
both `paths.RankedPath`s per direction are ranked on each dispatch. AC-004
(the duplicate-and-race dispatch assertion) exercises this incidentally —

AC-004 does not itself assert anything about ranking order or quality. This
is the same exercised-but-unanchored shape as GAP-4/BC-2.01.003 at v1.19:
harness machinery invokes the contract's mechanism without a test asserting
its outcome.

BC-2.02.003's actual subject — keep-alive-probe-driven per-path RTT/loss
tracking and quality-based adaptation — is **not** exercised: this harness's
`paths.NewPathTracker(1.0, 0.125)` trackers are static, `IsActive()` holds by
construction (`paths.go:115`), zero `OnProbe` calls occur, and no probe/loss
is simulated (consistent with this story's declared Non-Goals).
