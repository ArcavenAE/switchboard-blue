## BLOCKER (must fix in spec before implementation)
- **B1 — `mpFrame.ChanSeq()` is a phantom method.** Story L277 downstream flow calls `driver.downstreamARQ.OnAck(mpFrame.ChanSeq(), zeroSACK)`, but `multipath.Frame` (multipath.go:38-43) has only `OuterHeader [44]byte` + `Payload []byte` — no ChanSeq method/field. ChanSeq is a `halfchannel.ChannelFrame` field (halfchannel.go:66), deliberately absent from the 44-byte outer header. Story declares `internal/multipath` "None — read-only consumer" (L722) and Non-Goals forbid the outerassembler encode/decode round trip — so ChanSeq cannot be recovered at the OnAck call site as designed. Won't compile AND AC-006's mandatory OnAck postcondition is undischargeable. (Lens C BLOCKER-1; Lens B MED-1 — same defect.) FIX: thread the originating `halfchannel.ChannelFrame.ChanSeq` (already in scope at L269 send side; same synchronous tick/goroutine per Q3) into the OnAck call via closure capture; correct pseudocode in BOTH story L277 and placement-note L261; do NOT add a field/method to multipath.Frame.

## HIGH (must fix in spec before implementation)
- **H1 — AC-014 (the mandatory regression guard) is unimplementable against the specified types.** UNANIMOUS across all 3 lenses. `WaitForEcho` is void-return (story L337); `RoundTrip.done` is `chan frame.OuterHeader` (L324); `frame.OuterHeader` (frame.go:66-84) has no payload field; the RT-ID rides in payload bytes (Q5, `decodeRTID(payload)`). Completion path (L285) does `ch <- frameFor(payload)`, discarding the payload. But AC-014(b) (L641-643, the story-declared "load-bearing part") mandates "the returned frame's payload decodes to the sent RoundTrip id." No return value + payload-less carrier = unsatisfiable. AC-014 is the ENTIRE reason v1.1 exists (guard against the silent two-instance `(nil,nil)` failure); left unfixed the implementer ships the weak "did it return" assertion AC-014 explicitly forbids, silently defeating the guard. FIX: change `RoundTrip.done` to `chan []byte` (or `struct{Header frame.OuterHeader; Payload []byte}`), give `WaitForEcho` a return value carrying the delivered payload, reconcile L283-287/L322-337/L640-645 + Architecture Mapping L681.
- **H2 — halfchannel data race (both directions).** `halfchannel.go:89-90` explicitly: "HalfChannel is not safe for concurrent use... Tick() and Enqueue() [must be] called from a single goroutine or under external synchronisation." No mutex in the struct. Specified design accesses each half-channel from TWO goroutines with no sync: upstreamHC — `SendKeystroke` Enqueues on the test goroutine while the upstream ticker Tick()s; downstreamHC — `loopbackSink.SendInput` Enqueues (inside upstream-ticker goroutine) while the downstream ticker Tick()s. `driver.mu` guards only the `pending` map (L202/L285), nothing guards the half-channels. `just test-race` (CI) will fail; can lose enqueues / tear seq. (Lens B HIGH-1 — unique.) FIX: spec must add per-direction mutex serializing Enqueue+Tick, OR funnel enqueues into the owning ticker goroutine via a buffered channel so each half-channel is single-goroutine; add an AC asserting `-race` cleanliness.
- **H3 — upstream happy path unreachable: missing console attach/authorize.** `AccessNode.SendKeystroke` (session/upstream.go:276-300) returns `ErrConsoleNotFound` unless the console is attached, `ErrSessionMismatch` on mismatch, and the authorizer's error unless `Allow` passes. Shipped shard pattern (testenv.go:646-648) does `RegisterKey(sessionID.name, key, RoleFull)` then `access.Attach(key, sessionID.name)`. The story references the `AttachConsole` idiom by name 6× but NEVER specifies the RegisterKey(RoleFull)+Attach step for the loopback console. Without it every upstream keystroke returns ErrConsoleNotFound → sink never called → AC-004/005/006/014 happy paths all time out. (Lens C HIGH-2 — unique.) FIX: add to Q2/Task 4 (or CreateSession) that the driver RegisterKey(RoleFull)s + Attaches loopbackConsoleKey at construction and the authorizer Allows it.

## MED (fix in the same v1.2 pass)
- **M1 — AC-011 contradicts the unconditional pending-delete + AC-009.** Completion path (L285) deletes the pending entry unconditionally on delivery, independent of any waiter; in a no-loss harness every SendKeystroke drains its entry whether or not WaitForEcho was called. So AC-011's premise ("pending accumulates if WaitForEcho isn't called") is false, its test is timing-dependent, and it's in direct tension with AC-009 (which relies on the unconditional drain). FIX: reframe AC-011 as a non-blocking diagnostic OR respecify against a deterministic failure scenario (e.g. injected RT-ID decode mismatch). (Lens A MED; Lens C LOW-2.)
- **M2 — `OnAck` err swallowed + empty-tick 64-window coupling.** L277 captures `err` but never checks it; `Tick` increments seq on every tick incl. empty (halfchannel.go:118); `ErrAckOutOfWindow` fires at `ackSeq - nextExpected > 64` (arq.go:68) — reachable if env idles >64 downstream ticks (>3.2s at 50ms) before first echo (ticker starts at construction, first SendKeystroke later). First real OnAck returns ErrAckOutOfWindow, delivered=nil, err swallowed, WaitForEcho times out as mysterious "latency" — SOUL.md #4 silent failure. FIX: require the OnAck err be checked and fail loud; document/handle the empty-tick window coupling. (Lens B MED-2 — unique.)
- **M3 — `internal/testenv` extended source + ARCH-03 not in hash-bearing `inputs:`.** The downstream-only ARQ scoping rests on ARCH-03 §Downstream ARQ but ARCH-03 is only in `inputDocuments:`, not the hash-bearing `inputs:` list — a future ARCH-03 change wouldn't invalidate input-hash. FIX: add ARCH-03 (and per convention the testenv source anchor) to `inputs:` and recompute the hash. (Lens C MED-1.)
- **M4 — `toMPFrame`/`frameFor`/`encodeRTID`/`decodeRTID`/`zeroSACK` undocumented deliverables.** The two most defect-prone conversions (toMPFrame — where B1 ChanSeq loss occurs; frameFor — where H1 payload/header mismatch occurs) are absent from Architecture Mapping / File Structure. FIX: enumerate them with signatures; make toMPFrame's ChanSeq-preservation obligation explicit (ties to B1). (Lens C MED-3.)
