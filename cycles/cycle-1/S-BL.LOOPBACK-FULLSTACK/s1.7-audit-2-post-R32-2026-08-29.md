## Ranked gap list

### GAP-4 (MEDIUM, NEW) — BC-2.01.003 coverage not anchored; human-gate decision

BC-2.01.003 ("Upstream and Downstream Half-Channels Operate with Independent Clocks and Sequence Spaces", subsystem SS-01) is exercised by this story's two-half-channel design (the story builds and drives both an upstream and a downstream `halfchannel`/tick loop, each with its own clock and sequence space) and is partially asserted by the story's AC-002(b). It is **not currently anchored** in the story's `behavioral_contracts:`/`bc_traces:` frontmatter arrays or in the Anchors Consumed table.

Orchestrator disk-verified: BC-2.01.003's Precondition 3 requires idempotent replay (CAP-007). This harness's Non-Goals section explicitly excludes replay (per the story's own Q1 scope answer, consistent with placement-note Q1) — so a bare "anchor it" fix would be dishonest; the story cannot claim full BC-2.01.003 discharge.

**Disposition: HUMAN-GATE DECISION, not actioned unilaterally.** Two legitimate paths exist and the choice is a scope/anchor decision that belongs to the human, not the orchestrator:
1. Anchor BC-2.01.003 with a **partial/harness-scope disposition** — consistent with the precedent already set by this same story's BC-2.01.002 anchor, which is annotated "TO DISCHARGE partial, harness-scope" in the Anchors Consumed table (§1 of audit #1's report, row 2: "AC-003 (partial, harness-scope — honestly disclosed)").
2. Leave it unanchored and **explicitly record in Non-Goals** why BC-2.01.003 is deliberately excluded (the replay precondition it carries is out of scope).

Orchestrator's non-binding recommendation: option 1, for consistency with the BC-2.01.002 precedent already in this story. No story or note edit made this burst — recorded as a new Open Drift Item for the human approval gate.

### GAP-3 (MEDIUM) — S1.7-SYSTEMIC-SUBSYSTEMS-REGISTRY drift entry undercounts its own footprint

The existing Open Drift Items entry `S1.7-SYSTEMIC-SUBSYSTEMS-REGISTRY` (written by audit #1's remediation) is itself now inaccurate on two counts:

It should be **removed from the offender list**, not counted among the siblings still carrying the defect.
2. It names only the token `transport-layer`. Orchestrator disk-verified (frontmatter-`subsystems:`-array-scoped grep, not whole-file) a **larger and more varied footprint**:
   - `document_type: story` files carrying `transport-layer`: S-7.04-FU-PE-CONNECTOR, S-BL.BENCH, S-BL.PE-RECEIVE-LOOP, S-BL.RESYNC-FRAME, S-BL.ROUTER-RUNTIME, S-BL.TESTENV (6 files, not 4, and LOOPBACK-FULLSTACK is no longer among them).

   - `document_type: story-delivery` files carry additional invalid tokens whose coverage under the Subsystem Registry's MUST-rule is itself ambiguous (delivery ledgers are a different artifact class from stories, and ARCH-INDEX's MUST rule text names "story `subsystems:` fields" specifically, not delivery-ledger fields). The exhaustive frontmatter-array-scoped enumeration across the full corpus, and the MUST-rule-applicability question for `story-delivery` files, remain part of the **human-gated systemic sweep** — not resolved by this correction, only more accurately scoped. **Methodology note carried forward to the human sweep:** any future sweep of this class MUST use a frontmatter-`subsystems:`-array-scoped grep (e.g. `grep -n '^subsystems:' stories/*.md`, filtered to the token), never a whole-file grep — a whole-file grep false-positives on body prose that quotes a corrected-away token inside a fix-narrative changelog row (this story's own v1.18 changelog row, for example, quotes the removed `transport-layer` token inside its narrative describing the fix).
